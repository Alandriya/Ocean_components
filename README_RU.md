# Единый язык рисунков Ocean_components

Обновление основано на текущей ветке `main`, дерево GitHub `bdf06f2679b747bbb2d6839a60b787bace3d44db`.
Скопируйте содержимое архива в корень репозитория, сохраняя каталоги. Все Python-файлы полные, никаких патчей не требуется.

## Основной переключатель

В начале `main()` в `main_plotter.py`:

```python
plot_language = "en"
# plot_language = "ru"
set_plot_language(plot_language)
```

Оставьте только одну активную строку. Все задачи `main_plotter.py` используют её. `article_language` автоматически получает то же значение; параметры задач (периоды, диапазоны, язык файлов, палитры, плотности и т. д.) не требуют дополнительной настройки.

- `en` — английский (по умолчанию).
- `ru` — русский.

```bash
python main_plotter.py
```

Заголовки, оси, легенды, цветовые шкалы, подписи карты, номера областей, текстовые аннотации и подписи дат локализуются одним словарём в `Plotting/language.py`. Формулы MathText, имена моделей, числовые значения, данные и коэффициенты не меняются. Локализация применяется к Matplotlib Text при измерении и отрисовке, поэтому работает и для старого `save_figure`, и для прямого `fig.savefig`; после сохранения исходные строки восстанавливаются. Адаптер устанавливается один раз в процессе при импорте `Plotting` (или `Forecast_nn/plotting`, `Forecast_1d/plotting`), а не только в главной точке входа. Это означает, что сторонние Matplotlib-рисунки, которые строятся в том же Python-процессе после импорта пакета, также пользуются этим словарём. Новые специальные фразы можно добавлять в `_PAIRS`.

## Отдельные запуски

`main.py` также использует английский язык по умолчанию для карт статьи и графиков численных диагностик. Для отдельных CLI Forecast/Plotting допускается переменная окружения:

Linux / Bash:

```bash
OCEAN_PLOT_LANGUAGE=ru python -m Forecast_1d.plotting.plot_results --model sarima --split test
```

Windows / PowerShell:

```powershell
$env:OCEAN_PLOT_LANGUAGE = 'ru'
python -m Forecast_1d.plotting.plot_results --model sarima --split test
```

Для запуска из ноутбука Python:

```python
from Plotting.language import set_plot_language, plot_language_context
set_plot_language("ru")
# либо временно:
with plot_language_context("en"):
    # Здесь вызов функции отрисовки.
    pass
```

Явный `language="ru"`/`"en"` в функциях `Plotting.article_figures` действует локально и не переопределяет глобальный выбор после завершения функции.

## Что не изменено и ограничения

- Хранение данных, пути ERA5/коэффициентов, расчётные методы и параметры, визуальные диапазоны, цвета и состав рисунков не изменялись.
- Для совместимости с кэшем, видео и существующими потребителями сохранены имена обычных файлов (даже исторический суффикс `_eng`). Переключение языка может перезаписать обычный PNG; если нужно оставить обе версии, скопируйте одну перед запуском другой. Для рисунков статьи с отдельными языковыми суффиксами версии сохраняются отдельно.
- Готовые PNG/видеоролики не переводятся; для видео нужно заново построить исходные кадры.
- Словарь содержит известные статические и динамические подписи актуальных Matplotlib-модулей; произвольные новые фразы и пользовательские аннотации вне словаря остаются неизменными. Отдельная старая интерактивная 4D-функция Plotly (`draw_4D` в `Plotting/plot_EM.py`) не входит в `main_plotter` и этим Matplotlib-адаптером не локализуется.
- Проверено на Matplotlib в локальной среде. Не проводилась полная регрессионная проверка всех графиков на реальной ERA5 или CUDA.
